# ADR-004 — BioSTEAM is the engine, through one adapter

- **Status**: accepted (provisional choice; stage 4 implements it)
- **Date**: 2026-10-30

## Context

At `alpha-1.0` BioSTEAM runs in `workers/proforma_worker.py` behind the JSON-lines `SimWorker`
contract, with a shelf of four flowsheets, reference runs read against the `biorefineries`
package's own regression test (`flowsheets/shelf.py`, by `ast`), and scenario flowsheets
(`ethanol_glucose_v0`, `pha_sugar_v0`). The first domain of alpha 2.0 is cellulosic ethanol from
characterized biomass.

## Options

1. Keep the four-entry shelf.
2. A second engine.
3. Keep the worker and add a library plant runner and a composed cellulosic ethanol flowsheet.

## Decision

Option 3. The Proforma worker and the flowsheet pattern stay. `engine/library.py` discovers every
`biorefineries` plant the installed version exposes, builds each inside `package_defaults()`, reads
back its parameters as `ParameterSpec`s with `library-default` origins, runs with overrides
(`person-assumption` or `model-estimate`), prices and exports SFF. `flowsheets/cellulosic_ethanol_v0.py`
composes the `biorefineries.cellulosic` factories (pretreatment kind, fermentation kind `IB` or
`SCF`, reaction sets read from the package classes at import) and carries no number of its own.
Gates: per-reactant conversion sums, `InfeasibleRegion` turned into a refusal receipt, A→B→A
determinism after `empty_recycles()` and `tea._sales = 0`.

## Consequences

- fermOS, pureOS and Proforma keep their worker ops; their inputs become `Quantity` objects.
- NSKinetics keeps a socket in the adapter for a later phase.

## Implementation

### 4.2 (2026-10-30)

- `workers/library_plants.py` (in the Proforma worker) discovers every subpackage of the
  installed `biorefineries` by reading its namespace (`vars`), never by attribute access, because
  some packages build their whole plant when a name is asked of them (LAOs). The entry point is
  the first of `load`, a `Biorefinery` class and `create_system`; read beside it: its parameters,
  the configurations the package names (its own `configuration_names`, a submodule's, or the
  package test's `configurations`), a ProcessModel's scenario fields, the README's title, and from
  the package test file by `ast`, the plant's tests and the names its test uses for the feedstock,
  product and TEA. The package test is found through the distribution's metadata, never imported:
  importing `biorefineries.tests` broke the next build of another plant in the same worker
  (milk after cellulosic, measured).
- A build is fresh, inside `package_defaults()`: `cache={}` where the entry or the class `load`
  forwards to takes it, `load=False, save=False` for a ProcessModel, a ProcessModel class's own
  cache emptied while `load()` builds. Corn's compatibility change (two inlets on its SSF unit)
  is named in `COMPAT` with its reason and stated in every run's basis. The plant's parts are found
  by the package test's names, else the built plant's own system and scenario streams, else by
  inspection (the priced feed with the largest flow, the product with the largest sales), each
  saying how.
- Parameters read back: the main feedstock's flow, every priced boundary stream's price, the TEA's
  numeric settings, the plant cost index, the electricity price and each heating and cooling
  agent's prices, and each unit's design inputs as the vendored SFF toolkit's design-spec registry
  names them (a string-valued input is read back, never set). Each becomes a `ParameterSpec` with
  origin `library-default` and bounds that are conventions with their reasons.
- `engine/library.py`: the shelf `library_shelf.json`, regenerated by `pnpm library:discover`
  (discovery, then a build of each plant in each configuration) and held to the installed package
  by a `sim` test; parameters; a run (`library.run` artifact: the plant, its configuration, the
  simulator and settings, each compatibility change, each person's value as a named assumption,
  ten significant digits); the package test's values beside a run with no value of its own;
  `pnpm library:report` writes `docs/reports/library-regression.md`.
- Measured under biosteam 2.54.0 and biorefineries 2.35.1: fifteen subpackages, twelve plants;
  `ethanol` and `biodiesel` offer subsystem factories alone. 29 of 33 builds succeed: every cane
  and oilcane configuration, corn, cornstover, sugarcane, lipidcane, cellulosic and milk.
  LAOs, fattyalcohols, lactic and gas_fermentation stop inside the package's own code under the
  pinned BioSTEAM and stay on the shelf with the package's error. Against the package's own test:
  corn, sugarcane, lipidcane and ten of the thirteen oilcane configurations hold every value;
  cornstover holds nine of eleven (installed equipment cost −7.9 %, electricity consumption
  −5.2 %, as its reference run has since 2026-10-20); oilcane O2, O4 and O2* hold nine of eleven
  (utility cost and electricity production).
- A run is built afresh, so a run replays identically after another plant ran between (A→B→A,
  a `sim` test). The library run draws no Graphviz diagram: its SFF file's graph is its drawing.
- Not yet: the shelf's two hand-written reference entries (`cornstover_benchmark`,
  `corn_drygrind`) still serve the reference run and its screen beside the library plants
  `cornstover` and `corn`; they retire when the UI reads the library shelf (stage 7). A scenario of
  a ProcessModel (cellulosic's feedstock, gas_fermentation's carbon source) is not offered: a
  plant runs on its default scenario.

## Revisit condition

A second engine; NSKinetics once a kinetic model exists.
